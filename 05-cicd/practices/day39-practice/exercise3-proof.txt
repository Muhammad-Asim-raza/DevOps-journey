[ HOW CI/CD CHANGES EVERYTHING ]

  BEFORE CI/CD (Waterfall/Manual):
  ─────────────────────────────────
  Developers write code for weeks
  QA tests for weeks
  Ops deploys once a month
  Everyone blames everyone else
  'It works on my machine!'
  Fear: every deployment is terrifying
  Rollback: hours or impossible

  AFTER CI/CD (DevOps culture):
  ─────────────────────────────────
  Developers push small changes daily
  Tests run automatically (< 10 min)
  Deployment is boring and routine
  Team shares responsibility
  'Works everywhere because tests say so'
  Confidence: deploy anytime
  Rollback: one command, 30 seconds

[ THE SHIFT: DEV + OPS = DEVOPS ]

  Old world:
  Developer: 'Here's the code, good luck'
  Operations: 'We can't deploy this, it's broken'
  → Blame, conflict, slow delivery

  DevOps world:
  Developer writes code AND tests
  CI/CD runs the tests automatically
  Operations provides the pipeline
  Everyone owns the deployment
  → Shared ownership, fast delivery

[ THE THREE WAYS OF DEVOPS ]

  First Way: Flow (left to right)
    Code → Test → Build → Deploy
    Fast, automated, no handoffs
    CI/CD enables this

  Second Way: Feedback
    Monitoring tells you when things break
    Tests tell you BEFORE deployment
    Fast feedback loops

  Third Way: Continuous Learning
    Every failure = learning opportunity
    Post-mortems without blame
    Automation prevents repeated mistakes

[ CI/CD PREREQUISITES ]

  Technical:
  ✅ Version control (Git) - Day 19-25
  ✅ Automated tests - MUST write tests
  ✅ Containerization - Day 26-38
  ✅ Infrastructure as Code - Day 71-80

  Cultural:
  ✅ Small, frequent commits
  ✅ Feature branches + pull requests
  ✅ Everyone writes tests
  ✅ Deployment is routine, not scary
  ✅ Monitoring and alerting in place

[ WHY DEVOPS ENGINEERS OWN CI/CD ]

  DevOps engineers BUILD the pipeline
  (The factory floor, not the products)

  Responsibilities:
  → Design pipeline stages
  → Choose and configure tools
  → Write pipeline config (YAML)
  → Maintain runner infrastructure
  → Optimize build speed
  → Debug pipeline failures
  → Ensure pipeline security
  → Onboard new teams to the pipeline
