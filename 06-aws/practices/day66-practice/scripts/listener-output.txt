============================================
   LISTENER RULES, HTTPS, REDIRECT
============================================

[ 1. HTTPS listener with an ACM certificate ]
  aws elbv2 create-listener --load-balancer-arn $LB_ARN \
    --protocol HTTPS --port 443 \
    --certificates CertificateArn=arn:aws:acm:us-east-1:123456789012:certificate/demo \
    --ssl-policy ELBSecurityPolicy-TLS13-1-2-2021-06 \
    --default-actions Type=forward,TargetGroupArn=$TG_ARN
  TLS terminates at the ALB (cert from ACM, free, auto-renews).
  Traffic ALB -> target can stay HTTP inside the VPC, or be re-encrypted
  (HTTPS target group) if compliance requires end-to-end TLS.
  Pick a modern TLS policy; avoid old ones permitting TLS 1.0/1.1.

[ 2. Redirect HTTP -> HTTPS (modify the :80 listener) ]
  aws elbv2 modify-listener --listener-arn $HTTP_LISTENER_ARN \
    --default-actions 'Type=redirect,RedirectConfig={Protocol=HTTPS,Port=443,StatusCode=HTTP_301}'
  (Day 60 EKS Ingress annotation did the same thing for you.)

[ 3. Path-based routing ]
  aws elbv2 create-rule --listener-arn $HTTPS_LISTENER_ARN \
    --priority 10 \
    --conditions Field=path-pattern,Values='/api/*' \
    --actions Type=forward,TargetGroupArn=$API_TG_ARN
  Lower priority number is evaluated first. Default rule is last.

[ 4. Host-based routing ]
  --conditions Field=host-header,Values='admin.yourdomain.com'

[ 5. Fixed response (maintenance page / block path) ]
  --actions 'Type=fixed-response,FixedResponseConfig={StatusCode=503,ContentType=text/plain,MessageBody=Back soon}'
