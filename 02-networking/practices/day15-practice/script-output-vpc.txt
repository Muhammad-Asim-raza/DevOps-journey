sg-application:
  Inbound:  3000/tcp sg-load-balancer (from LB only)
  Inbound:  22/tcp   10.0.0.0/16 (SSH from VPC)
  Outbound: all      0.0.0.0/0

sg-database:
  Inbound:  5432/tcp sg-application (from app only)
  Outbound: all      10.0.0.0/16 (VPC only)

sg-bastion:
  Inbound:  22/tcp   YOUR-OFFICE-IP/32 (SSH from office)
  Outbound: 22/tcp   10.0.0.0/16 (SSH to VPC)

[ TRAFFIC FLOW ANALYSIS ]
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

User Request Flow:
  Internet
  → Internet Gateway
  → Load Balancer (public subnet)
  → Application Server (private subnet)
  → Database (db subnet)
  → Response follows same path back

Admin SSH Flow:
  Admin laptop
  → Internet Gateway
  → Bastion Host (public subnet, port 22)
  → App Server (private subnet, port 22)
  (database accessible from app server)

Outbound Update Flow:
  App Server (private subnet)
  → NAT Gateway (public subnet)
  → Internet Gateway
  → Package repositories
  (internet cannot initiate connection back)
